# DenoiseAI — Backend

FastAPI service that serves the trained `denoising.h5` CNN for AI image denoising.

## Model architecture (inspected from `denoising.h5`)

- **Type:** Residual U-Net (`residual_unet_denoiser`) — 2 downsampling stages,
  2 upsampling stages with skip connections, and a final residual `Add` so the
  network predicts a noise residual rather than the clean image directly.
- **Input:** `(None, None, None, 3)` — fully convolutional, accepts **any**
  image resolution as long as height and width are divisible by 4.
- **Output:** `(None, None, None, 3)` — same spatial size as the input fed to it.
- **Normalization:** pixel values scaled to `[0, 1]` (`image / 255.0`), matching
  how the model was trained.

Because the network is fully convolutional, and because this project's own
training script (`model/denoise.py`) trained on native-resolution crops of
real sensor noise, the backend **never resizes the uploaded image**. Doing
so would partially average out the very noise pattern the model learned to
remove. Instead it runs **tiled, native-resolution inference**:

1. The image is split into overlapping tiles (512×512, 32px overlap).
2. Each tile is reflect-padded up to the next multiple of 4 (required by
   the two 2× pooling stages), denoised, then cropped back to its exact
   original size.
3. Overlapping tile predictions are blended (weighted by coverage) to
   avoid visible seams at tile boundaries.

The output is always exactly the same pixel dimensions as the input.

## Endpoints

- `GET /` and `GET /health` — health checks; `/health` also reports whether
  the model loaded successfully.
- `POST /predict` — accepts a multipart file upload (`file`), returns the
  denoised image as a PNG (`image/png`) stream.
- `GET /docs` — interactive Swagger API docs (auto-generated by FastAPI).

## Local development

```bash
cd backend
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

The backend runs at `http://localhost:8000` (docs at `http://localhost:8000/docs`).

The model is loaded once from `model/denoising.h5` at startup — it is **not**
reloaded per request.

## Environment variables

Copy `.env.example` to `.env` (or set these in your hosting provider's
dashboard):

```
FRONTEND_URL=*
```

Set `FRONTEND_URL` to your deployed Netlify URL in production so CORS only
allows your real frontend, e.g. `FRONTEND_URL=https://denoiseai.netlify.app`.

## Deployment (Render / Railway / Google Cloud Run / any Python host)

1. Push this repository to GitHub.
2. Create a new **Web Service** pointing at the `backend/` directory.
3. **Python version:** TensorFlow 2.20 requires Python 3.9–3.12. Some
   platforms (Render included) default to the newest available Python,
   which is too new for TensorFlow and will fail the build with
   `No matching distribution found for tensorflow`. `backend/runtime.txt`
   pins this to `python-3.11.9` — most platforms (Render, Heroku) read it
   automatically. If yours doesn't, set an environment variable instead:
   ```
   PYTHON_VERSION=3.11.9
   ```
4. Build command: `pip install -r requirements.txt`
5. Start command:
   ```
   uvicorn main:app --host 0.0.0.0 --port $PORT
   ```
   (a `Procfile` with this exact command is already included for platforms
   that use one).
6. Set the `FRONTEND_URL` environment variable to your Netlify URL.
7. Once deployed, copy the backend's public URL and set it as `VITE_API_URL`
   in the Netlify frontend's environment variables.

> **Note:** `denoising.h5` (~5–6 MB) ships inside `backend/model/`. Do **not**
> move it into the frontend project — TensorFlow/Keras models are never
> deployed to Netlify; they only run on the Python backend.
